# Raspberry Pi ダッシュボード実行手順

取引ボットの`data/state_*.json`と`logs/decisions_*.csv`を読み取る、監視専用Webアプリです。売買・取消・設定変更の操作はなく、APIキーやシークレットをブラウザへ送信しません。データベースも不要です。

## 配置

プロジェクトを次のように配置します。

```text
/home/pi/gmo_coin_trade/
├── gmo-trading-bot/
│   ├── gmo_trading_bot.py
│   ├── .env              # 取引ボットの設定・APIキー
│   ├── data/
│   └── logs/
└── dashboard/            # このWebアプリ
    ├── package.json
    ├── src/
    ├── api/
    └── ...
```

別の場所に置く場合は、ダッシュボード側の`.env`で`BOT_DATA_DIR`、`BOT_LOG_DIR`、`BOT_ENV_FILE`を変更してください。取引ボット側の`.env`からは、`TRADE_CRON`・スプレッド上限・リスク上限などの非秘密項目だけを読み取ります。

## 1. Node.jsを準備

Raspberry Pi OS 64bit、Node.js 22 LTSを推奨します。

```bash
node -v
npm -v
```

Node.js 22以降が入っていない場合は、Raspberry Pi OSの公式手順またはNodeSourceのNode.js 22 LTSを導入してください。

## 2. ビルドして起動

```bash
cd /home/pi/gmo_coin_trade/dashboard
cp env.example .env
npm install
npm run build
npm start
```

PCやスマホをラズパイと同じLAN/Wi-Fiへ接続し、次のどちらかを開きます。

```text
http://raspberrypi.local:3000
http://ラズパイのIPアドレス:3000
```

IPアドレスはラズパイ上で`hostname -I`で確認できます。開発中にホットリロードを使う場合は`npm run dev`です。通常の監視では本番ビルドを`npm start`で実行してください。

## 3. 実データ接続を確認

取引ボットを先に1サイクル以上実行してください。

```bash
cd /home/pi/gmo_coin_trade/gmo-trading-bot
source .venv/bin/activate
python gmo_trading_bot.py --once
```

ダッシュボードのAPIを直接確認する場合：

```bash
curl -s http://localhost:3000/api/trpc/dashboard.snapshot | head -c 500
```

画面上部のセレクターには、GMOコイン公式の公開API `/public/v1/symbols` から取得したレバレッジ銘柄（`_JPY`で終わる銘柄）、ボットの`.env`に設定した銘柄、既存の状態ファイルにある銘柄を重複なく統合して表示します。状態ファイルがある銘柄は実データを表示し、まだない銘柄は別銘柄へ置き換えずに**初回判定待ち**と表示します。

公式APIの取得は5秒でタイムアウトします。一時的な障害時は、`.env`と状態ファイルの銘柄を使って監視を継続します。公式銘柄・ボット設定・状態のいずれも読めない場合だけ**デモデータを表示中**と出ます。

## 4. systemdで自動起動

まず`npm run build`を完了させてから、次のユニットファイルを作成します。

```bash
sudo nano /etc/systemd/system/gmo-dashboard.service
```

ユーザー名や配置が異なる場合は`User`、`WorkingDirectory`を変更してください。

```ini
[Unit]
Description=GMO Trading Bot Dashboard
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/gmo_coin_trade/dashboard
Environment=NODE_ENV=production
Environment=PORT=3000
ExecStart=/usr/bin/npm start
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

有効化して起動します。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gmo-dashboard
systemctl status gmo-dashboard
journalctl -u gmo-dashboard -f
```

画面やAPIを変更した後の更新手順：

```bash
cd /home/pi/gmo_coin_trade/dashboard
npm install
npm run build
sudo systemctl restart gmo-dashboard
```

## 表示の見方

- **稼働中**：状態ファイルが定期的に更新されています。プロセスの存在を直接保証するものではありません。
- **更新停止**：ボットの`TRADE_CRON`から求めた実行間隔と最低15分の猶予を超えて、状態ファイルが更新されていません。ボットのプロセスと`bot.log`を確認してください。
- **取引停止**：日次損失停止フラグが有効です。翌JST日付まで新規注文しません。
- **評価資産・損益**：ボットがCSVに記録した値を使用します。dry-runは仮想資金です。
- **チャート**：最新8日分のCSVにある`MARKET`イベントから作成します。24時間／7日を切り替えられます。
- **ログ**：最新500件をAPIで読み、画面では最大200件を表示します。各項目をタップすると理由と結果を確認できます。
- **システム情報**：実データ接続時にメモリ使用率、対応環境ではCPU温度を表示します。

## セキュリティと運用上の注意

- このアプリにはログイン機能がありません。**LAN内の信頼できる端末だけ**からアクセスしてください。
- ルーターで3000番ポートをインターネットへ開放したり、ポートフォワードしたりしないでください。
- 自宅外から確認したい場合は、TailscaleなどのプライベートネットワークまたはSSHトンネルを使い、監視APIを直接公開しないでください。
- 読み取り専用でも、資産・注文・取引戦略の情報が画面に表示されます。共有ネットワークでの利用は避けてください。
- ダッシュボードを停止しても取引ボットは停止しません。ボット自体は従来どおり別プロセス／別サービスとして管理してください。
- ラズパイの時刻をNTPで同期してください。時刻ずれがあると「稼働中／更新停止」の判定やログ時刻が不正確になります。
